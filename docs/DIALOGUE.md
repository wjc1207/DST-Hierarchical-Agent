# 聊天、指令模式与自主模式

游戏左上角有运行开关和模式切换按钮。切换模式会先暂停当前动作。

- **指令模式**：切换后直接在游戏聊天框输入需求，例如“收集五个木头”。DeepSeek 规划任务看板，执行器持续推进。看板全部完成后，DeepSeek 根据最新状态检查原始需求；还缺步骤就继续规划，确认需求已完成才回复并进入待命。无法执行时可以解释原因并暂停，等待玩家补充。
- **自主模式**：开启后持续自主生存；聊天内容用于补充或修改安排，阶段目标完成后继续规划。`goal("长期目标")` 仍可设置长期生存方向，修改目标不会自动开启控制。

指令模式待命时也接收聊天；自主模式关闭时普通聊天只发送给游戏。`/` 开头的游戏命令不进入 DeepSeek。玩家的自然语言照常发送到游戏聊天，DeepSeek 通过 `TheNet:Say` 以当前玩家角色发言，带 `[DeepSeek]` 前缀，同服玩家也能看到。超过游戏 150 字限制的回复按 UTF-8 字符分条、间隔发送；新指令会取消尚未发出的旧回复分条。Agent 回复直接走原生网络接口，不会作为玩家新指令再次触发规划。

## 中途打断

收到自然语言消息时，Lua 立即提高控制版本、停止当前可取消的动作、暂停看板。Python 丢弃旧规划的接纳资格，并在当前 HTTP 请求返回后终止旧请求的后续查询或重试，再处理最新消息。旧请求已发出的 HTTP 调用可能需要等待响应或 30 秒超时，但不会重新控制角色。

新规划包含原始指令、最近最多 8 条玩家消息、最新状态、原看板与已取得进度，以及最近 3 轮有效规划对话。DS 可保留或调整任务，显式取消已经过时的任务。纯聊天回复后恢复原看板；安排发生变化时按修订后的看板继续执行。已开始的锅内烹饪等世界过程不会被撤销。

等待消息重规划时不执行自由探索或顺路采集；启用控制期间，现有本地与 JEV 生存安全处理继续生效。指令模式等待定时任务或受阻时，也不会借机开展无关工作。

单独输入 `停止`、`暂停`、`取消` 或 `stop`、`pause`、`cancel`，会在本地立即关闭控制。恢复按钮保留旧进度；待命后发出新消息会开始新的指令轮次。界面暂停后玩家负责操控角色。

## 完成与回复协议

正常看板可带 `reply`（单行，最多 256 个字符）。不需要新看板时，DS 可返回：

```json
{"kind":"agent_reply","outcome":"reply","reply":"我正在收集剩余的木头。"}
```

`outcome` 可为 `reply`、`blocked` 或 `completed`。`completed` 仅用于指令模式，需要 `evidence` 描述现场证据；接纳时会再次检查当前看板没有未完成任务。原始需求的语义是否满足由 DS 结合现场判断，工具返回成功本身不能作为完成依据。

回复通过 `send_agent_feedback(text, revision, message_id, finish=false)` 送入 Lua 桥接。HTTP 响应直接使用 UTF-8 中文，避免游戏 JSON 解码器无法识别的 `\uXXXX` 转义。消息 ID 去重，版本号隔离旧指令；完成回复同时将指令模式置为待命。旧回复不能停掉新指令。日志中的 `replan_reason=player_message` 和 `agent_reply outcome=...` 用于排查过程。
