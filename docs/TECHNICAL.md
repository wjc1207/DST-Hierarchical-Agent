# 技术说明（1.8.8，MCP-only）

[项目首页](../README.md) · [English](TECHNICAL.EN.md)

当前只保留 MCP → Lua 原生执行。旧键鼠输入、窗口查找／聚焦、游戏日志轮询、预测动作缓冲及其专属测试已移除。游戏日志仍可用于人工排查，但不再作为 Python 的控制通道。

## 目录与职责

```text
mcp_agent/   模型调用、规划、优先级看板、搜索意图、连接检查
mcp_server/  MCP 工具、状态缓存、动作队列、本机 HTTP 桥接
common/      游戏事实规则、看板格式、配置路径、时间测量
scripts/     Lua 感知、地图寻路、原生执行、实时安全验证
data/        DSTKnowledge.txt、Klei 区域资源配置快照
tests/       当前 MCP、共享规则及 Lua 的离线回归
tools/       从本地原版代码提取资源配置
docs/        技术说明
```

根目录保留 Mod 入口、README、依赖文件和测试入口。`.env` 与 `logs/` 位置不变。

| 职责 | 实现 |
| --- | --- |
| 长期需求、优先级、依赖、预算、后台复核 | `mcp_agent/daily_planner.py` |
| DS 规划空窗、安全变化时选择本地动作 | `mcp_agent/jev_client.py` |
| 先完成可见任务，再为最高优先任务寻找来源 | `mcp_agent/priority_board.py` |
| 选择搜索目标、区域目的地、已知来源／未知分支 | `mcp_agent/navigation_intents.py` |
| 两个模型使用同一事实投影 | `mcp_agent/model_state.py` |
| 通行检查、区域内前沿、绕障、路线与连续移动 | `modmain.lua`、`scripts/jev_exploration.lua` |
| 动作合法性、接近、采集／制作、验证和紧急中断 | `scripts/jev_native_executor.lua` |

Python 决定为何、往哪里寻找资源；Lua 决定具体怎么走。`navigation_intents.py` 只调度 Mod 提供的合法导航选项，不计算人物行走路径。共享规则不调用游戏、窗口或操作系统输入接口。

## 调度、导航与安全

白天手持火把时，Lua 执行器自动卸下以节约燃料，无需 JEV 决策。该维护步骤在控制连接有效时运行，空闲或正在逃跑也可执行，不替换当前动作及其报告；尚未观察到卸下效果时每秒重试。黄昏、夜间与营火旁的卸火把仍沿用既有规则。

完整看板格式、搜索预算和 Klei 先验见 [目标与导航设计](GOAL_NAVIGATION.md)。DS 后台维护持久优先级目标；每 1/4 天复核，不清空有效目标和进度。执行器先选可见任务，没有可推进任务时，查位置记忆、已知来源区域、生成先验，再探索未知分支。Lua 连续执行移动和原生动作；危险或状态变化可立即中断。JEV 只在 DS 规划空窗和危险处置时触发，计划外机会判断已关闭。普通资源类型／工具能力变化只让执行器重新检查看板，不调用 JEV。

安全入口包括敌人瞄准、受伤、照明变化／夜间缺光，以及已知生命、饥饿、精神值低于各自上限的 30%；没有食物也会触发低饥饿求助。Lua 在执行期间跨过警戒线或恶化到更低的 10% 区间时中断，中断后由 JEV 选择具体处置动作。JEV 选择 `wait` 后，未变化的危险不会反复请求，可恢复合法的看板工作；新可用补救动作、新敌人或原生安全中断会再次触发。未知数值不当作零值。

JEV 选择逃跑后，Lua 在同一动作中完成连续移动与受阻换向。约 0.8 秒没有至少 0.3 单位的移动进展时，立即从实时可通行路线中选择其他方向；失败方向在当前位置 2 单位范围内暂避 8 秒，不会给整个逃跑动作加 15 秒失败冷却。若可通行方向都曾受阻，则优先重试最早受阻的方向，避免所有候选都被隐藏；只有实时确实没有可通行路线时才报告 `no_safe_escape_route`。移动超过局部范围或时间到期后，该方向恢复资格。原生报告／事件中的 `escape_reroutes` 记录换向次数；受伤与昼夜变化仍不会取消正在执行的逃跑，整段动作保留原有超时和取消边界。

没有看板、看板为空／已完成，或所有剩余任务当前没有可执行动作或路线时，立即请求 DS 评估更新，期间由 JEV 临时代行，不再先空等 15 秒。仍保留有用的未来任务；同时只运行一个 DS 请求，失败后的 15 秒退避期间继续临时控制。临时探索不被暂时无法推进的旧目标束缚，仍遵守原生合法性和失败动作的短暂暂停。旧任务重新可执行或新看板可推进后，恢复自动执行；JEV 临时决定返回时若发现主线已能继续，就交回主线，已开始的原生动作按原有完成／安全中断规则处理。

跨区域行走先检查入口两端及完整接近路径，直线受阻时使用已观察陆地上的安全绕行；不能因为眼前一小段可走，就把最终无法接近的危险入口列为可达。开始前往某区域后，Lua 保持仍有效的第一跳及入口两端坐标，不因短路线重新出现就掉头。绕障短暂经过相邻区域时，继续接近原定入口；抵达选定的下一跳区域或改变导航目标后才重新选择入口。行走进展记录跨资源事件和绕障途中的区域标签变化保留：累计主动行走 12 秒内，下一入口的剩余路径估计未缩短至少 2 单位，且已走至少 16 单位或几乎原地不动时，暂停该入口 30 秒。模型等待、采集绕行及拓扑确认等待不计入窗口；正常绕障按路径距离判断进展。到达固定过界点后不再重复发送零距离行走，等待拓扑确认最多 3 秒，超时以 `region_confirmation_timeout` 暂停对应入口。`graph.route_pause` 和原生中断原因 `route_no_progress`／`route_gateway_unavailable` 用于排查；Python 不会因此封禁前往同一区域的其他入口，也不会推断资源已耗尽。

看板导航随 `start_action` 下发 `navigation_targets`，包含全部已就绪的本地目标，排除已完成、依赖未满足和搜索受阻的任务。Lua 不因无关资源出现／消失停止；位移至少 4 单位后，只有实时可用动作能推进仍未满足的目标，才以 `goal_action_available` 中断并交回执行器。覆盖拾取、合适树木／含目标矿物的石块（检查工具、耐久、路径）、制作、建造和食物；树木／矿石不必先引起可拾取资源集合变化。Python 等待动作时仍检查规划变化与原有区域／全局搜索预算，需要重调度时先取消并等 Lua 确认，避免连续行走拖延新规划。DS 空窗期省略过滤器，继续使用原有资源集合变化交接；危险始终即时中断，JEV 的额外机会判断保持关闭。`navigation_target_count` 与 `navigation_review` 可用于排查。

DS 请求使用稳定的 `system` 前缀：规划规则、DSTKnowledge、完整 Klei 区域类型资源表、能力／物品名称与别名、固定执行限制和规划策略。历史对话随后排列，末尾 `user` 只保留实时状态、看板进度、近期结果和本次请求原因；历史状态中的重复知识也会清理。区域先验是静态生成知识，不是当前存档已发现区域，实际拓扑和资源记录始终以实时状态为准。API 返回用量时，终端输出 `daily_plan_usage` 的缓存命中／未命中 token；未报告不等于零。

每次动作使用作出选择时的 `observation_id` 和选项名称；服务检查所有权和时效，Lua 根据实时状态最终验证。排队／运行不等于完成，必须等待原生结果。同一执行器同时只执行一个动作。

纯语义动作序列为已有 MCP 调用方兼容，不包含旧键鼠路径。新的 DS 输出是优先级看板。外部看板工具保留显式自动执行语义，不能与 Python 看板调度竞争控制权。

科学机器的公开看板目标／动作仍为 `sciencemachine`／`build_sciencemachine`，Mod 统一映射到 Klei 的配方和实体 ID `researchlab`。可建造判断、缓存制作、放置均使用真实配方名；附近实体上报为 `prefab=sciencemachine, game_prefab=researchlab`，让现有看板、动作序列和原生完成验证使用同一名称，同时保留真实 ID。已有缓存配方可继续放置，无需再次消耗材料。新实体被实际观察到后才确认完成；手动建成后被观察到的科学机器也会保留为已验证里程碑。

营火选址由 `scripts/jev_campfire_siting.lua` 与 Mod 完成：单独扫描可燃掉落物和实体，不受常规附近实体白名单／数量上限影响。在角色当前位置 3–6 单位内寻找可通行、避开已知危险的建造点，与可燃物至少相隔 5 单位；季节范围倍率大于 1 时扩大间距。制作前和实际放置前各检查一次，无安全位置则隐藏建造选项，不回退到不安全位置。已制作但未放置的营火可保留，稍后放置不重复消耗材料。

砍树按客户端可见的成长动画判断大小，服务端组件可用时读取成长阶段／剩余工作量。耐久足够且路径可达的已观察目标中优先大树，再选中树、小树，同大小按距离；未知阶段保守预留 15 次斧子使用。大树在近身范围外时先接近再砍。砍树／采矿后的拾取围绕原作业点 6 单位独立扫描，不受常规 40 实体上限影响；附近旧掉落物、堆叠合并和部分拾取均继续处理。每段接近单独计时，避免把砍树时间误算为移动停滞。等待掉落复制和拾取后的短暂稳定期后才确认清空，持续无库存效果则明确失败，危险仍可中断。

`collect_berrybush_juicy` 将采摘和落地浆果拾取合为一次操作：已发出采摘请求且原目标变为不可采后，复用上面的独立拾取流程，围绕原灌木收集多汁浆果。整段最多 30 秒；不能仅凭灌木采空、请求已发送或原有库存判定成功，必须有新浆果入包，并等附近浆果拾取结束。没有收到新浆果会明确报告 `harvest_loot_not_received`。普通浆果灌木和单独拾取地面浆果保持原行为；危险和取消仍能中断。

砍树／采矿接近阶段进入原生动作按钮的目标选择范围（中心距离小于 6 单位），且当前路径为安全直达时，就交给带实体目标的原生 CHOP／MINE 动作；最终站位由游戏 locomotor 按碰撞半径处理，不再要求走到距实体中心 1.2 单位内。仍需绕路时继续沿已验证的路径接近，工具、耐久、危险中断及作业后拾取保持验证。这里的 6 单位是动作交接范围，并非隔空砍伐／采矿距离；普通采集和落地物拾取仍使用原有接近逻辑。

两个模型都收到 `construction.campfire` 的选址状态、原因和安全间距；计时记录包含 `campfire_siting_ms`。这是建造位置检查，未改变之后烹饪时的接近行为，也不能据此确定掉血原因。

## 启动、配置与排查

从项目根目录运行：

```powershell
python .\mcp_agent\mcp_probe.py
python .\mcp_agent\mcp_agent.py --loop --execute
```

自动循环自行启动 `mcp_server/mcp_server.py`，不要再运行同端口服务或 Codex 的 DST MCP 连接。工具契约见 [MCP 说明](MCP.md)。

- 模型密钥：根目录 `.env`，也可用 `--env` 指定。
- 桥接令牌：`logs/mcp_bridge.json` 与安装的 `scripts/jev_bridge_config.lua`；升级保留原文件。
- 规划知识：[data/DSTKnowledge.txt](../data/DSTKnowledge.txt)。
- 区域先验：[data/worldgen_resources.json](../data/worldgen_resources.json)，不是当前存档的实体清单。
- 规划进度：`logs/task_board.json`、`logs/task_board.jsonl`。
- 计时：`logs/mcp_timing.jsonl`、`logs/mcp_transport.jsonl`。

Python 通过 MCP 读取状态，不轮询 `client_log.txt`。Mod 日志是诊断，不是另一套控制接口。旧数字小键盘和 F 键动作入口也已移除，取消使用 MCP `cancel_action`。

升级时复制 `mcp_agent/`、`mcp_server/`、`common/`、`data/`、Mod 入口和 `scripts/`，保留原配置和日志，重新进入世界并重启 Python。不要覆盖 `.env` 和生成的桥接配置。

## 测试

运行 `python run_tests.py`。测试使用假模型、假游戏或本地协议模拟，不调用真实模型或操作游戏。Lua 检查可用 Fengari 运行 `tests/exploration_spec.lua`，直接调用原生动作句柄，不注册键盘事件。
