# 建筑记忆、前往建筑与家

本功能供 DeepSeek 优先级看板和外部 MCP 客户端使用。新动作标记 `planner_only=true`，不进入 JEV 的候选或状态投影，也不进入规划空窗期的普通探索候选。

## 记忆范围

Lua 在角色附近单独扫描实际观察到的建筑，不受常规附近实体白名单或 40 个实体上限影响。识别结构、科技建筑、营火／火坑及已注册放置配方对应的非背包实体，包含玩家手动建造的建筑。

扫描漏掉已知实例时，仅按已记忆的 GUID 查询当前已加载实体，不遍历未探索建筑；确认消失会输出 `[JEV_DST_PLACE]missing` 及判定原因。

每个建筑档案使用不透明的 `building:<数字>` 稳定 ID（首次通常使用首次观察的 GUID），`guid` 单独记录当前客户端实体 GUID，二者不能互相推算。保留真实 prefab、名称、位置、所在区域、碰撞半径、首次／最近观察时间和已知用途。科学机器保留真实 `researchlab`，同时提供语义别名 `sciencemachine`。

- `observed`：本次附近扫描看见。
- `unconfirmed`：离开视野，保留上次位置；不是“已经消失”。
- `missing`：原位置连续至少三次处于完整扫描范围内、缺失持续至少一秒，并未通过当前绑定 GUID 复核找到实体；曾离开视野的建筑返回后给予十秒副本加载宽限期。保留记录供规划复核。单次漏检先标为 `unconfirmed`，不直接判消失；不完整扫描／离开范围会重置待确认计数，重新观察到同一实例时恢复。
- 最多保留 256 个实例；路线受阻不会删除建筑记录或推断建筑被拆除。

记忆和家属于当前游戏世界及本地角色，保存在 Lua 世界对象中。重启 Python 不会清空；退出／重进世界或切换角色实例会重新建立。**第一版不做跨游戏会话落盘，也不做地面／洞穴跨分片导航。**

## 查询

MCP 新增只读工具：

```text
query_places(query="", building_id=null, offset=0, limit=12, refresh=false)
```

返回分页建筑列表、当前 `home`、已知建筑对应的 `anchors`（`ready=true` 表示当前已抵达且可安全设家）、快照年龄和会话 ID。搜索匹配 prefab、实例 ID、游戏当前名称及语义别名。每页最多 24 个建筑；`refresh=true` 请求新的游戏快照。

DeepSeek 使用同名只读 function tool 查询该次规划的不可变快照。完整建筑目录不注入初始提示词或历史对话。已有配方查询与地点查询共用最多 8 轮响应／每轮 4 次工具调用的预算。

## 看板目标

```json
{"type": "visit_building", "building_id": "building:12345"}
```

前往已观察的指定实例。跨区域复用已有安全区域路线；进入目标区域后继续接近建筑。寻找建筑周围可站立的位置，避开建筑占地和已知危险，最终必须重新看见该建筑并到达接近点。仅进入区域、走完某段路线或靠近旧坐标，不算到达建筑。

```json
{"type": "set_home", "anchor_id": "building:12345"}
```

设置家。`anchor_id` 仅接受查询返回的建筑 ID `building:<GUID>`，不再生成或接受当前位置 `here:*` 锚点。建筑离开视野后仍可选作锚点；角色在规划期间移动不会使这个 ID 失效。执行器先前往该建筑，重新观察并确认抵达后，在建筑旁的安全落脚点设置家。实际落脚点会在抵达后确定，避免走到建筑占地中心。建筑消失／记忆被淘汰时明确阻塞，不会偷偷改选其他建筑。执行时仍复查坐标、所在区域、距离及安全路径，不接受模型自填坐标。附近有科学机器不会自动把它设为家。

同一建筑的设家请求允许落脚点偏移最多 **2 个世界单位**（含边界），不再要求浮点坐标完全相等。命令接收和实际写入家位置两处使用相同范围；最终保存最新验证过的安全落脚点。建筑身份改变、尚未抵达、偏移超范围、坐标无效或安全检查失败仍会拒绝。

```json
{"type": "return_home", "home_id": "home:1"}
```

返回指定版本的家。每次设置家产生新的 `home:<revision>`，旧指令不能静默改去新家。到达家附近 1.5 单位以内且已验证接近路径时完成。家的落脚点独立于建筑：关联建筑被拆除后仍保留该地点。

三种目标均放在普通 `tasks[].target` 中，遵循优先级、依赖、导航预算、取消和危险中断。DeepSeek 最终输出会核对目的地来自本次已观察数据。未设置家时先设置，确认生效后再查询新的 home ID 并安排返回。

每次前往按任务完成一次并锁存。之后要再次访问同一建筑／返回同一个家，请使用新的任务 ID；新访问不会与已完成旧访问合并。看板仍最多六项，需明确取消不再需要的任务。

## 制作与安全

需要在家附近停留时使用 `stay_home`，不是重复提交 `return_home`。普通任务的
`start_at` 与驻留的 `duration`／`end_at`、范围限制见 [任务时间与驻留](TASK_TIME.md)。

配方缺科技时，DeepSeek 可先查询建筑，再安排 `visit_building`，然后安排制作。建筑访问完成只是一次到达经历，**不代表当前仍在科技范围内，也不会永久解锁配方**。制作前仍由原生配方条件重新检查；不从“曾经去过”推断当前科技满足。

家是位置，不保证当前有光、有食物或安全。夜晚没有装备便携照明时，新地点导航不会允许角色离开火光；安全处置仍由现有 JEV 候选处理。普通可执行本地任务优先于地点长途行走，前往途中仍可因安全、任务更新或目标变化中断。

## 客户端实体重载与稳定建筑身份

服务端建筑仍存在时，客户端远离再返回也可能获得新的本地实体 GUID。建筑档案 ID、家锚点和任务目标保持稳定，只有当前 `guid` 和 `binding_revision` 更新。添料选项、火势遥测、前往建筑及放置锚点都使用这一映射；底层动作仍绑定实际当前 GUID，旧动作不会静默改为新实体执行。

自动重新绑定须同时满足：原建筑曾离开观察范围、尚未确认消失、原 GUID 不在本次观察列表、真实 prefab 相同、坐标偏差不超过 0.25 世界单位，并且新旧双方都是唯一匹配。多个候选、附近同类建筑、原实体仍在场或已经确认就地删除时不合并。此前离开过视野的建筑允许十秒等待复制加载，之后仍经完整扫描确认缺失；一直在观察范围内的实际删除仍按原有一秒规则处理。

这是客户端基于观测的建筑位置档案，不声称能区分未观察期间在完全相同位置重建的同类建筑。世界／角色会话范围、256 条记忆上限保持原样。现场匹配歧义时保留独立记录，不猜测。

重新绑定输出 `[JEV_DST_PLACE]rebound id=... old_guid=... new_guid=... prefab=... distance=...`；缺失日志也包含当前绑定 GUID。可用 `query_places` 检查稳定 `id`、当前 `guid` 与 `binding_revision`。
