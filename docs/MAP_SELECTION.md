# 看图选址与前往世界坐标

DeepSeek 可按需调用规划查询工具 `query_map`，查看模组已观察区域的 PNG 地图。
图片以游戏世界坐标为准：右侧为 `+x`、上方为 `+z`，不随游戏相机旋转。
这是一张根据观察数据绘制的地图，不是截图，也不包含隐藏世界信息。

## 选址流程

1. 准备建立或搬迁营地时，调用 `query_map` 查看地形、道路、建筑、资源与危险记录。
2. 返回首选坐标、理由和可选备选点；加入 `move_to` 任务。承诺前往时可开启专注。
3. 营地建筑任务依赖移动任务完成，避免执行器因材料够用就在出发前建造。
4. 到场后按当前碰撞、照明、威胁和放置条件执行；不合适时重新规划。
5. 建筑建好后，下一轮查询 `query_places`，用建筑 ID 执行 `set_home`。
6. 后续营地建筑填写 `target.placement={anchor_id:建筑ID,radius:10}`，在已有锚点附近建设；
   `camp_site` 不作为放置范围。详见 [建筑位置约束](PLACEMENT.md)。

沿用当前已接受看板中的 `camp_site`，首选和保留的备选坐标不变时，无需再次调用
`query_map`。修改说明、到达半径或删除备选点也不要求重读；首次选址、更换首选／
备选坐标或新增备选点时仍必须读图。没有当前看板时才参考上一份看板，不能用更早
对话中的旧营地绕过搬迁检查。所有返回坐标仍需通过当前已观察可通行陆地校验。

坐标只是选址候选和移动目的地，**不直接成为家锚点**。已有合适建筑时可以复用，
不因模型重新选址就重复建科学机器。备选点记录在计划里，不会绕过 DS 自动执行。

```json
{
  "goal": "前往已观察空地检查并建立临时营地",
  "camp_site": {
    "x": -40, "z": 64, "reason": "靠近已知资源，周围有可检查的空地",
    "backup": {"x": -32, "z": 60, "reason": "附近的备选陆地"}
  },
  "tasks": [
    {"id":"inspect_site","title":"前往候选营地","priority":1,"focus":true,
     "target":{"type":"move_to","x":-40,"z":64,"arrival_radius":2}},
    {"id":"camp_station","title":"在候选地建立科学机器","priority":2,
     "depends_on":["inspect_site"],"target":{"type":"structure","prefab":"sciencemachine"}}
  ]
}
```

示例坐标必须替换为当前地图上实际已观察的陆地。制作材料、已有科学机器限制等仍
沿用现有规则；示例不表示每次选址都必须建造科学机器。

## 图像与信息边界

- `query_map` 可选 `center_x`、`center_z`（成对填写）及 `span`（32–512 世界单位）
  调整视窗。默认显示观察范围，最大跨度 512；需要时可查看其他视窗。
- PNG 为 1120×1360，带较淡的世界坐标网格、地形色标、玩家 `P`、家 `H`、建筑编号、
  采样得到的道路范围与已记录威胁 `!`。优先使用本机游戏的小地图树木、树苗、草丛、浆果丛、
  矿石、科学机器及人物图标。建筑编号 `B1` 等对应图片底部及查询元数据中的完整 ID。
  深色空白是未观察区域，蓝色是不可通行／水域。
- 图标右上方的琥珀色空心小圆圈表示历史记录，不代表仍可采；密集重叠的同类图标
  显示数量。最多显示 128 个记忆资源，加当前附近实体；坐标舍入造成的重复记录会合并。
  地形格分辨率为 4 个世界单位，道路在已观察格内细采样到 1 个世界单位；这不能证明某个点恰好有足够建筑空间。
- 地图仅覆盖模组当前世界会话实际观察到的区域，不等同于玩家完整游戏地图。
  最多导出最近发现的 4096 格；达到上限后 `truncated=true`，旧格移出导出范围。
- 游戏端缓存地图行，传输层只发送变化格子，重连或丢失基版本会请求完整重同步。
  心跳不携带地图。Python 只在 DS 请求地图时渲染图片。
- 查询结果的图片以 `user` 消息附加在所有工具回复之后。历史只保留文本快照和计划，
  不反复保存或重发旧图片。原始地图格子也不填入普通模型文本。
- 本次查询基于发起规划时的冻结快照，带 `observed_at` 和地图版本；执行时重新验证。

最新实际查询图保存在 `logs/planner_map.png`，视窗、时间和版本在
`logs/planner_map.json`。CLI 看板显示 `Camp site` 与 `Backup`，完整信息也在看板日志中。

### 游戏图标与本地缓存

渲染器自动查找模组所在的游戏目录、标准 Steam 安装位置；也可在 `.env` 中设置
`DST_GAME_DIR` 为游戏根目录或 `data` 目录。首次看图时只读加载本机
`data/minimap/minimap_data*.xml` 与对应 KTEX 图集，使用 Pillow 自带的 DXT5 解码器，
裁切并处理 UV 方向、预乘透明度。无需下载额外转换程序或修改游戏文件。

裁出的 PNG 图标缓存于 `logs/map_icons/<资源签名>/`，内存中复用已加载图标。
游戏图集更新后缓存自动失效，损坏或缺失的缓存会重新生成。游戏美术不随项目源码
打包；缓存仍受现有 `logs/` 忽略规则保护。无法读取游戏素材时使用树、枝条、草丛等
图形符号回退，不退回难辨认的字母散点。查询元数据标注 `icon_source` 和实际使用数量。

图片是按观察数据摆放图标，不是游戏截图；图标尺寸、聚合不代表实际碰撞体积。
普通营火不冒用永久石头火堆图标，科学机器、炼金引擎及树种使用对应图标。

## 移动动作与限制

任务目标 `move_to` 的 `x`、`z` 必须有限且处于 ±100000 内，`arrival_radius` 为
0.5–4，默认 2。落点必须属于导出的已观察可通行格。Python 只表达目的地，不计算
每步方向；Lua 在收到指令后复查落点、路径、建筑占地、威胁与当前照明，复用现有
区域导航及安全接近路径。未知路段不会被坐标请求授权穿越；无已知安全路径时返回
原因，必要时先探索再前往。途中路径变化、危险、取消和搜索预算仍可中断。

中间路点或进入目的区域不算抵达，实际进入指定半径才完成。完成一次后保留任务
完成记录；再次前往使用新任务 ID。驻留仍限制普通工作范围，坐标移动不会绕过它。
当前照明规则仍要求夜间装备火把才能开始这类导航，不扩展照明道具或 JEV 选项。

外部 MCP 客户端可直接调用：

```json
{"name":"move_to","arguments":{"x":-40,"z":64,"arrival_radius":2,"observation_id":"本次观察凭据"}}
```

也可使用 `start_action(choice="move_to", destination={x,z,arrival_radius?}, ...)`。
返回动作 ID 后通过 `get_action_status` 查看实际结果，或 `cancel_action` 取消。
坐标看板要求 Python 调度，不支持原生 `auto_execute=true`。Lua 必须上报
`coordinate_navigation=true`，旧模组明确拒绝新动作。

## 安装与验证

更新 Python、`modmain.lua` 和 `scripts/`，新增 `common/coordinates.py`、
`mcp_agent/map_view.py`、`scripts/jev_coordinates.lua`。使用同一个 Python 环境安装
`requirements-mcp.txt`，其中 Pillow 用于 PNG 绘制。重新进入世界并重启控制循环。

默认 `deepseek-flash` 官方接口支持 `user` 消息中的 `image_url` 图片块：
[DeepSeek Vision 文档](https://api-docs.deepseek.com/guides/vision/)。自定义模型／代理也
必须支持该格式；不支持图片时会报告请求错误，不会声称看过地图或静默换模型。

离线验证：`python run_tests.py`；Lua 回归新增 `tests/coordinates_spec.lua`，并扩展
`tests/exploration_spec.lua` 的真实模组路线及地图重同步测试。实机仍需验证模型选址、
长距离多区域路径、碰撞及实际地图信息密度。


## 道路渲染

旧版本把道路格中心按八方向互连，容易生成不存在的斜线、三角形和梯子。新版不再从相邻采样点推断道路连接：

- 在实际已观察到且中心可通行的地形格内，通过游戏 `RoadManager:IsOnRoad` 读取 4×4 子格，绘制采样得到的道路路面；相邻的真实采样区域自然衔接，未采样的空隙不补线。
- 每轮感知最多细采样 8 个地形格，最多 128 次道路子格查询。缓存有效 30 秒，命中缓存不消耗预算，旧格先复用原采样；动态改路在预算内逐步刷新。不可通行格不采样，失败查询不伪装成没有道路。
- 地图行的第七项为 16 位整数掩码：从西南开始，先按 x 向东，再按 z 向北；位为 1 表示该 1×1 世界单位子格的中心采样落在道路上。0 表示已采样且没有道路点，缺项表示尚无细采样。
- 旧六项地图行仍兼容，但只显示棕色道路采样点，不再连线。新版部分格仍可能暂时显示点，等待后续预算补齐。
- `planner_map.json` 增加 `road_fine_cells`、`road_samples`、`road_coarse_samples` 和 `road_connections_inferred:false`，用于区分新旧数据。

地图道路用于选址参考，不改变导航、碰撞和照明校验。修改后同步 Lua/Python，重新进入世界并重启 Python；旧地图 PNG 不会自动改写，下一次 `query_map` 会使用新渲染。
