# 伙伴已见建筑记忆与返回（0.5.1）

伙伴原先只回传当前 20 单位内的建筑，普通 `move` 也只允许 20 单位以内的坐标。离开科学机器采集材料后，即使模型记得旧坐标，也不能靠一次远距离 `move_to` 返回。这会导致错误地寻找或重建科学机器。

## 观察与记忆

服务端在生成伙伴观察时，记住该伙伴实际看到的建筑，最多保存最近观察的 64 个。记忆绑定伙伴实体，玩家新消息和本机 Python 重启不会清空；服务器重启和重新生成伙伴仍不保留。不会读取玩家地图，也不扫描全世界寻找科学机器。

`places.buildings` 包含 `id/guid/prefab/name/x/z/last_seen_at/distance/status/arrived`。ID 为本服务器会话的 `building:<GUID>`；远处未重新观察时状态为 `unconfirmed`，保留最后看到的位置。离开观察范围或从截断列表中消失不构成建筑被拆除的证据。明确访问时发现实体确实已删除才标记 `missing`；烧毁等不可用状态单独处理，不把附近另一座同类建筑当成原建筑。

`buddy_places(query?,building_id?,offset?,limit?)` 是只读 MCP 查询；DeepSeek 的工具为 `query_places`，直接复用 `common.places.query_places` 的过滤和分页规则。日志的 `known_building_count/recent_buildings` 记录记忆数量和最近建筑状态，便于区分没有见过、远处未确认与已确认消失。

## 返回与制作

看板目标为 `visit_building {building_id}`，原生动作也使用同名参数。Python、MCP 和服务端都校验它确实是伙伴记住的建筑，不接受任意未见 GUID 或模型编造的坐标。

服务端使用原生 `GoToEntity` 前往建筑，抵达 3 单位内才确认到达，允许从 20 单位之外返回。普通 `move_to` 的 20 单位限制仍保留。持续 20 秒没有真实移动进展会停止，5 秒无进展可清理路径重试（等待原生路径搜索时留 15 秒），总旅程最多 300 秒。新消息、停止指令和客户端心跳丢失仍会中断。建筑记忆不保证路线可达，也没有全图区域图或跨水路规划。

到达后刷新伙伴自身的实际科技范围。需要科技的制作任务用 `depends_on` 依赖返回任务；是否可原型制作仍以当前配方、材料和科技遥测为准，抵达不直接解锁配方或提供免费材料。提示词要求优先返回足够等级的已见科技建筑，避免因远处未确认而直接重造。

0.5.1 将 `building_arrived` 的匹配建筑 ID、到达标记和距离回执纳入任务完成记录，避免服务端已经确认到达，但随后观察落在范围边界外又重复返回。其他建筑的回执、失败结果或未确认到达不能完成该目标；后续制作仍独立检查最新科技和材料。

这批迁移包含建筑记忆与返回，不包含设置家、驻留、未见建筑搜索，箱子的远距离存取也仍需先返回再进行局部操作。

## 实测

更新模组后重进世界并重启 Python，先让伙伴靠近一次科学机器，建立这版新记忆；更新之前的旧对话不作为服务器见过建筑的证明。带伙伴离开 20 单位后输入：

```text
/buddy do 回到刚才的科学机器旁，制作一根绳子
```

确保有相应材料。检查动作应为 `visit_building`，抵达后才 `craft`，途中不应靠小步盲搜寻找科学机器或重建一台。再验证中断、建筑真实拆除、路径受阻等情况。自动化测试覆盖记忆保留、权限、远距离移动、依赖和科技刷新，实际游戏表现仍需验证。
