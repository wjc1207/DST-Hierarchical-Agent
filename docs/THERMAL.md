# 温度安全与火势控制

客户端从角色原生温度接口读取 `player.vitals.temperature`、`overheating`、`freezing`，并提供当前过热阈值、预警阈值和恢复阈值。只有温度组件或客户端复制值存在时才上报读数，不把初始化默认温度当作观测。

默认过热阈值为游戏的 70，提前 5 度开始避热，降到阈值下方 10 度后恢复任务；角色自定义过热阈值优先。`thermal.active` 在恢复前保持，避免在预警线附近往返。

## 添料

每次只添加一份。旧按份数目标在火熄灭或只剩余烬时允许添料；已达到低火档（`fire_section >= 2`）或读不到已燃烧火堆的档位时暂停添料。体温达到预警线或仍在降温时同样暂停。新的燃料比例目标可以继续补到保守区间下界达到目标；第四档不能证明超过 75% 时停止继续投料。每次发出原生添料动作后等待至少 2 秒，让火势复制更新，再决定下一份。

`refueling.targets` 包含火源身份、可观测的火势档位、燃料百分比（仅原生组件可读时）和暂停原因。普通客户端从火焰特效的当前动画读取档位，推导保守燃料区间并标注估算；不将范围写成精确百分比，也不推算剩余燃烧时长。暂停原因包括 `fire_already_sufficient`、`temperature_too_high`、`fuel_settling`。

暂停不清空已验证的累计份数，也不将未投出的燃料记为完成。DS 应减少、取消剩余添料任务或安排稍后检查，不通过新任务 ID 强行添加更多燃料。

## 降温

Lua 在体温预警时中断普通动作；Python 主循环优先执行原生 `cool_down`，越过专注和驻留约束，降温期间不计安全驻留时长。遇到主动敌人仍优先处理敌人。JEV 的可选动作范围保持原样，`cool_down` 由确定性安全逻辑管理。

避让采用 2／4 单位的短步，只选择离附近已点燃营火或石头火堆更远的位置。整段路径检查地形和威胁，也不能先靠近火源再绕出。夜间没有已装备火把时，沿途必须实测有足够照明；若没有安全的照明路线，有现成火把时允许在火边装备，再避让。否则原地等待并上报原因，不向黑暗中移动。暂时仅使用现有火把装备逻辑，不新增提灯或矿工帽支持。

移动过程持续复查，路线失效即停；卡住的位置短暂避开后另选。完成一步避让不代表体温已经恢复，需达到恢复阈值才继续看板。看不到附近火堆时不猜测热源和避让坐标，报告 `no_safe_lit_cooling_route`。

DS 和 JEV 提示明确：普通站在火边不会自动回血。应结合真实体温、威胁和动作结果判断掉血原因。

## 日志与更新

`logs/mcp_timing.jsonl` 每轮记录 `temperature`、`overheating`、`freezing`、`heat_warning_threshold`、`thermal_status`、`thermal_reason` 和最多四个附近火源的 `fire_state`。温度不可读时为 null。传输性能日志增加 `thermal_ms` 和 `refueling_ms`，用于观察新增检查开销。

更新 Lua 和 Python 后，需要重新进入世界并重启 Python 控制程序。离线测试包括 `tests/thermal_spec.lua` 和 `tests/test_thermal.py`；实机仍需检查火焰动画复制、夜间照明边缘与降温效果。
