# 任务时间、驻留与饥饿维持

时间属性属于任务，和 `target` 分开。普通任务可选 `start_at`；驻留使用新目标
`stay_home`，并且必须在任务上提供 `duration`、`end_at` 中的一项。`hunger_ratio` 与燃料比例目标 `refuel`
额外支持可选的任务级 `duration`，用于持续维持饥饿水平。

## 普通任务：天黑后建造营火

```json
{
  "id": "night_fire_1",
  "title": "第一晚建造营火",
  "priority": 1,
  "focus": true,
  "start_at": {"day": 1, "phase": "night"},
  "target": {"type": "structure", "prefab": "campfire"}
}
```

开始时间之前为 `scheduled`，不调度、不锁存完成，也不激活专注。条件达到后才按
原有目标执行；建造一次并确认结果即可完成。`start_at` 是最早执行时间，不是截止
时间；如果条件已过，任务仍可执行，但仍受当前材料、照明、路径等原生限制约束。
规划空窗的普通候选也会排除只属于未开始任务的动作；紧急安全处置可覆盖此限制。

`start_at` 可用 `{day, progress}`，进度范围 `[0,1)`，例如 `0.75` 为该游戏日的 3/4；
也可用 `{day, phase}`，阶段为 `day`、`dusk`、`night`。两种形式不能混填。省略 `day`
时，在接收看板时绑定当前游戏日；建议 DS 显式填写。日内进度不等于某个固定昼夜阶段。
省略 `start_at` 表示前置条件满足后立即具备执行资格。

## 驻留：3/4 天开始回家，待到下一次天亮

```json
{
  "id": "home_night_2",
  "title": "第二晚回家驻留",
  "priority": 1,
  "focus": true,
  "start_at": {"day": 2, "progress": 0.75},
  "end_at": {"phase": "day", "next": true},
  "target": {"type": "stay_home", "home_id": "home:1", "radius": 12}
}
```

`home_id` 来自 `query_places`。到开始时间后，复用已有返回家动作，必须实际抵达家，
然后进入驻留。到家不立即完成任务，也不会为了普通探索离家。可以执行范围内的
采集、制作、进食等兼容任务；没有可做工作时保持驻留，不交给 JEV 去做无关探索。
驻留的专注标记不会阻止兼容的本地工作，其他普通专注目标仍沿用原先的选择规则。

`end_at` 同样支持 `{day, progress}`、`{day, phase}`。`{phase, next:true}` 在任务开始
具备资格时绑定下一次该阶段：比如当前黄昏／夜间的下一次 `day` 为下一天白天；
当前已经是白天时，下一次 `day` 也为下一天。之后不会每次观察都向后推迟。
固定结束时间不因路程、规划延迟或避险顺延；错过截止且没有完成有效驻留时为
`expired`，不能因为之后站在家里就补记成功。

要抵达后停留四分之一天，将上例的 `end_at` **替换为**：

```json
"duration": 0.25
```

`duration` 单位为游戏天，范围 `(0,7]`。只累计实际抵达后安全处于驻留范围内的观察
时间，回家路程不计。游戏暂停时不计时；避险离开或观察到主动威胁时暂停累计，
之后恢复。使用辅助模组快进时间会按前后观察到的游戏时间推进结算，不能证明中间
未经观察的操作。游戏时间倒退会使该驻留任务失败，需要新任务重新规划。

## 持续维持饥饿水平

```json
{
  "id": "eat_dusk",
  "title": "持续维持饥饿水平",
  "priority": 2,
  "focus": true,
  "start_at": {"day": 1, "phase": "dusk"},
  "duration": 0.25,
  "target": {"type": "hunger_ratio", "at_least": 0.7}
}
```

不填 `duration` 时，仍是达到目标一次就完成。填入后，以游戏天计时，范围 `(0,7]`：
开始时间和前置任务满足，且能够读取真实饥饿值及游戏时间后立即开始计时，不等待先吃到目标值。

- 达标后进入 `maintaining`，不会提前锁存为完成。监测期间允许其他任务执行，专注标记暂时不占执行范围。
- 低于目标时重新进入补食状态，恢复专注范围，并按任务优先级安排补食；必要时中断尚未完成的普通工作。原生照明、路径、食物可用性及安全限制仍然生效。
- 到期时当前饥饿值达标则 `done`；仍低于目标、无法读取饥饿值或玩家已死亡则 `expired`，返回原因，之后吃饱也不补记成功。该任务的依赖项要等整段维持窗口完成后才放行。
- 避险期间窗口继续随游戏时间流逝，不顺延；游戏暂停则时间不推进。辅助模组快进按观测到的游戏时间结算，不能证明未观测期间始终达标。

`at_least:0.7` 是补食触发下限，观察和动作耗时可能令实际饥饿值短暂低于它。补食达标后仍保留原截止时间，不重新计时。看板以百分比显示饥饿进度，另行显示 `maintain remaining=...d`。

结果中的 `maintenance` 提供 `started_at`、`deadline`（绝对游戏天，第一天从 0 开始）、`elapsed_days`、`remaining_days` 和 `phase`。相同任务 ID、目标、`duration` 与 `start_at` 的规划更新保留计时；只修改优先级、标题或专注也不会重置。更改目标或时间属性会开始新的任务状态，明确的新一轮维持应使用新 ID。重启 Python 不恢复旧窗口，需要重新规划。

燃料比例目标也可用 `duration` 维护，保守区间及判定详见[添燃料](REFUELING.md)。`hunger_ratio` 和 `refuel` 暂不支持 `end_at`；制作、建造等任务仍不能填写 `duration`。饥饿维持由 Python 调度，不增加 JEV 的可选动作；燃料比例还依赖新版 Lua 的档位区间和原生添料校验，需同步 Lua、重新进入世界并重启 Python。

## 参数错误只影响该任务

- 驻留同时填 `duration` 与 `end_at`：该任务为 `failed`，原因是二者互斥。
- 驻留两者都没填、饥饿任务填写 `end_at`，或其他普通任务填写 `duration/end_at`：同样作为单任务时间错误返回。
- 无效时间、非正停留时长、可静态确定的结束早于开始，也返回具体原因。
- 结果中的 `task_errors` 包含 `task_id`、`reason`；任务带 `timing_error`，CLI 显示
  `failed` 和原因。其他有效任务保留，依赖这个失败任务的目标仍会等待修复。
- 普通结构／配方／依赖等原有看板错误仍遵循原来的整板验证规则。

## 范围和安全

`radius` 范围 6–30，默认 12 个世界单位，绑定指定版本的家。多个同时生效的驻留
任务只能使用当前有效的同一个家，执行其半径交集，各自独立计时。

Python 筛选动作，MCP 用当前家复核中心位置，Lua 再检查目标、接近路径、作业拾取
余量及每个内部行走步骤。边界检查采用保守缓冲；位置在范围内但需要长绕路、超出
范围的掉落物拾取或无法确认路径的动作可能暂不执行。驻留时不做普通远程探索。
这不是移除原有路径、工具和照明限制，也不自动点燃建筑。

安全决策仍由 JEV 负责，逃跑等安全动作不附带驻留边界。危险缓解后，如果驻留窗口
仍有效，执行器返回家再继续。家被重新设置为其他 ID 时，不静默切换目标，要求 DS
重新评估。已完成驻留使用新任务 ID 才能再次请求。

## 更新和边界

使用 Python MCP 优先级主循环执行。外部 `submit_task_board` 可以提交并查询任务
错误，但原生 `auto_execute=true` 不支持定时／驻留看板，会明确拒绝，避免提前执行。

同步 Python、`common/task_timing.py`、`common/residence.py`、`mcp_agent/residence.py`、
`scripts/jev_residence.lua` 及更新的 Lua 文件，重新进入世界并重启 Python。
驻留动作要求 Lua 上报 `residence_constraints=true`，旧版本不能默默忽略边界。
本版计时状态保存在当前 Python 控制会话内；重启控制循环后不自动恢复已累计的停留
时长，需要 DS 重新规划。现有建筑／家记忆的世界会话限制保持原样。


## 观察顺序与返家动作复查

等待模型回复期间会持续读取新状态；当次动作仍使用原观察凭据校验原目标，但计时、进度和搜索预算只接受较新的真实 `observed_at`。读到较旧快照时改用最近真实观察，不倒写计时，并在 `mcp_timing.jsonl` 记录 `observation.stale_ignored`。预测状态不替换真实观察；较新观察里的游戏时间确实倒退时，原有失败提示仍保留。

驻留尚未抵达时，返家动作的选择和执行中复查使用相同的驻留约束，不会因其他专注任务或资源监控列表变化而反复取消。已经到达、任务取消／变更、时间窗口结束或家发生变化时仍停止旧返家动作。普通返家任务和其他工作继续遵守原有专注范围。
